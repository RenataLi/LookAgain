# Given-page region selection: prospective development and small held-out evaluation

Prepared 2026-09-27. **Design specification; execution requires the separate source/code/configuration locks below.** This is a locally timestamped protocol, not external preregistration. Earlier experiments, sources, raw records, metrics and conclusions remain frozen. No model outcomes from this stage informed this document.

## Question and remaining privilege

Can a prompted, frozen Qwen3-VL-4B-Instruct choose a useful region from a fixed nine-window bank using only the question and a low-resolution page overview, better than choosing uniformly from that same bank? The selector is an inference procedure with no fine-tuning and no learned gain predictor. The sole primary evaluation contrast is selected-native accuracy minus the **exact uniform expected native-crop accuracy** within each source.

All policies receive the same **annotation-selected answer page**. The new regional policy removes annotation-derived ROI localization, but page selection remains privileged. This is given-page extractive document QA on a previously source-audited DUDE training subset, not full-document DUDE, page retrieval, a representative benchmark sample, or a leaderboard result. Public pretraining exposure is unknown. The prior privileged-ROI study motivates this question but neither supplies a nonprivileged policy nor establishes this policy's efficacy. Its annotation-derived crops differ in location and size from this grid, so old privileged-crop scores are not an interchangeable oracle baseline without a dedicated paired experiment.

## Model, inputs and nine candidates

Freeze Qwen/Qwen3-VL-4B-Instruct revision `ebb281ec70b05090aa6165b016eac8ec08e71b17`, BF16, SDPA, greedy generation and the existing frozen backend. No weight update, external detector/OCR, text-reasoning controller, question-specific candidate generation or high-resolution search is added. Every request is fresh, with no prior assistant answer and no shared cross-call KV state.

For source raster width W and height H, let cw=floor(W/2), ch=floor(H/2). Horizontal starts are `round((W-cw)*i/2)` for i=0,1,2; vertical starts use H,ch analogously. Python half-to-even rounding is fixed. Number the Cartesian product row-major 1–9. ID5 is the center window. Every window has the same integer size and area at most 25% of the page; the candidate bank reaches all outer boundaries; realized coordinates on odd dimensions are logged. This grid depends only on dimensions, never on the question, canonical answer, OCR or annotation ROI. Require both source dimensions at least 512 pixels, supported native dimensions and processor sizing for all candidates; no hidden minimum-resolution upsampling or answer-dependent window expansion.

The selector receives only the original question, the same unmodified 256-visual-token overview, and fixed textual descriptions of the nine windows/IDs. No native crop thumbnails, drawn grid, OCR text, answers/variants, annotations, source URLs/filenames, evidence descriptions, candidate scores, or old responses enter the request. Bind the literal `SELECTOR_SYSTEM` and `SELECTOR_INSTRUCTION` in [the new request builder](../experiments/region_selection_core.py), including `Question: ` plus the original question and the fixed normalized-coordinate list, and bind actual processor inputs. Those normalized descriptions are nominal; actual integer coordinates are logged rather than asserted to equal the decimals exactly on odd dimensions. Source-cluster identifiers are for pairing/provenance and deterministic sampling only; they are not prompt text.

Use one selector call with maximum 16 newly generated tokens and no prefilled answer. Require a full response match to `\s*REGION:\s*([1-9])\s*`. Reject explanatory prose, multiple IDs, wrong case/prefix, punctuation, out-of-range IDs, and any truncated generation. A format failure selects center 5 with a recorded invalid status/fallback reason. It is retained under intention-to-treat scoring. A valid choice of 5 and a fallback to 5 remain distinguishable. No selector retry or response-dependent extra call is permitted. Runtime/processor errors are execution failures, not format fallbacks.

After selection is committed and persisted, fresh answer requests use the original overview and one native candidate crop with the unchanged neutral two-image instruction and `ANSWER:` prefix/parser. The selector response, region ID/direction, rationale and confidence never enter the answerer's chat. Candidate location changes only the supplied image pixels. Native crop generation uses source pixels, with the fixed 1024 visual-token ceiling and no native upsampling. The selected-degraded control projects that same box into the 256-token overview and resizes it to the exact native output dimensions. It must share the overview, prompt bytes, second-image dimensions, processor grids and token counts with its selected-native counterpart.

Direct256 and highres4096 use only the provided page at their respective budgets. All ordinary answer calls have maximum 64 newly generated tokens and the frozen copy-span instruction. Invalid/empty parsed answers score zero; truncated responses are retained and valid parsed answers are scored as produced. No semantic review changes an automatic grade.

## Physical calls and executable policies

For each source, physically generate: one selector response, direct256, highres4096, nine native-candidate answers, and one selected-degraded answer: 13 calls. Persist the selector decision before dependent processing; the selector process never reads candidate outcomes or scoring labels. Candidate-answer call ordering is seeded and recorded. A policy choosing a candidate reuses that candidate's single stored answer, including when selector, center and random coincide. Do not decode twice and keep a favorable response.

Report these policies separately:

- **Always selected native:** selector, then its chosen native crop answer.
- **Center:** native crop 5; no VLM selection call.
- **Uniform random:** one ID drawn independently of labels using SHA256(`region-random:20260927:` + example_id), converted from digest bytes to a big-endian integer to seed a local `random.Random`, then `choice(range(1,10))`; no VLM selection call. In addition, compute its exact expectation by averaging all nine candidate outcomes.
- **Direct256 and highres4096:** one full-page answer each, without selection.
- **Selected-degraded:** same selector decision plus matched overview-derived crop; secondary information control.
- **Three confidence-gated policies:** direct256 first; only on a declared low-confidence/missing-confidence branch invoke the selector and chosen native crop answer. Stop branches invoke no selector model call.

The offline nine-crop bank provides counterfactual policy outcomes and an exact uniform expectation. It is not nine free online observations. No executable policy may inspect which crop is correct, choose the best answer afterward, or use annotation overlap to decide. A candidate-set oracle can be reported only as a label-aware upper-bound diagnostic for this finite bank, never as model performance or deployment cost.

## Development confidence thresholds and policy freeze

The always-select prompt, grid, parser, fallback and rendering rules are fixed before development outputs and are **not tuned after development accuracy is seen**. Engineering may repair implementation defects with explicit evidence, tests and a new lock before development; it cannot inform outcome-driven source selection.

Use the existing direct256 `mean_token_logprob` as an uncalibrated confidence ranking. It includes all generated tokens measured by the backend, including termination tokens where present. It is not calibrated probability of correctness or gold-answer likelihood. Compute its development-only 25th, 50th and 75th percentiles using finite direct256 values and NumPy's linear quantile interpolation. The thresholds depend on no reference, grade, semantic judgment, evaluation score, or selected-crop response. Use finite logprobs from all development direct responses, including responses with invalid answer parses. Record the exact contributing IDs/values and counts; missing logprob is recorded explicitly; nonfinite numeric confidence is a validation error, not a routing value. If no finite development logprob exists, threshold locking fails rather than inventing thresholds.

Create a separate **threshold/policy lock** after development completion and before evaluation generation. It binds the development run, quantile implementation, three numerical thresholds, always-select policy, evaluation cohort, code/configuration and timestamp. Report all three gated policies descriptively, never choose the best after seeing evaluation outcomes. Zoom exactly when direct `mean_token_logprob <= threshold`; ties zoom. Missing confidence (`None`) also zooms. An invalid direct answer parse does **not** itself force zoom: this is a pure generation-confidence baseline, not a combined format-repair policy. Nonfinite numeric records are rejected. Empirical zoom fractions need not equal 25/50/75% because of ties and missing-confidence branches. No policy threshold is selected to maximize development accuracy. Evaluation outcomes remain unread until all 780 planned calls and the strict validator are complete.

## Scoring and statistics

Reuse `experiments/dude_metrics.py` unchanged. Primary accuracy is exact equality after casefold and collapsed whitespace to any source-approved **unchanged original** reference. Preserve punctuation, numeric formatting, signs and units. The canonical source reference remains mandatory and immutable. This custom source-validated EM is not official DUDE EM. The secondary metric is the pinned author's scalar ANLS against original canonical answers only, preserving its existing quirks and response-layer invalid-parse zero.

For source i, let y_ij be primary EM for native candidate j and s_i be the committed selector/fallback ID. Define U_i=(1/9)sum_j y_ij and d_i=y_i,s_i−U_i. The **sole primary evaluation statistic** is mean_i d_i over the 60 evaluation source clusters. Compute a 95% paired percentile interval from 10,000 source-cluster bootstrap draws using `random.Random` with seed `20260927` and linear percentile interpolation. Each draw carries all nine candidates and every policy outcome together. N=60 clusters, not 540 independent crop presentations. The empirical resampling interval is conditional on this selected source population; residual dependence and nonrepresentative sampling limit broader inference. The selected-minus-uniform-expectation difference is fractional, so the primary analysis uses the paired bootstrap. Exact McNemar and binary discordance tables do not apply to this expected baseline.

Report all policy means, interval, source-level differences, actual coverage, selector-ID distribution/fallbacks, exact-uniform expectation and single-random realization. Development results are separate and descriptive. ANLS, selected-native minus selected-degraded, center/random/direct/highres contrasts, confidence curves and localization/coverage diagnostics are secondary and unadjusted; none can replace the primary after outcomes. A label-aware annotation-overlap audit occurs only after selector commitment and does not remove failed cases or prove actual reading of the selected evidence.

A positive primary interval supports better selection than uniform within this fixed bank/population; it does not establish superiority to center/highres or a favorable compute tradeoff. A nonpositive or uncertain result is reported as such; it does not establish equivalence or rule out further study. There is no automatic controller-training gate, and no claim to have learned expected information gain. A future confirmatory study needs a frozen chosen policy, separate untouched sources and its own power/design argument.

## Relation to prior work

This is an applicability and diagnostic study, not a novel region-selection method. [GapSight](https://arxiv.org/html/2608.21762v2) already learns review/utility/region prediction from target-model loss differences. [SPARC](https://arxiv.org/html/2602.06566v3) already separates relevance localization and answer generation, including training-free Qwen3-VL-4B experiments. [ZoomEye](https://arxiv.org/html/2411.16044v3) demonstrates training-free search with confidence-dependent stopping. These primary sources were checked on 2026-09-27; none is claimed as a locally reproduced baseline. The present controls ask a narrower question about given-page document evidence, fixed grids, annotation isolation and actual measured costs.
