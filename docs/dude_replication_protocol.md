# DUDE: matched-detail replication protocol

This document describes the design fixed before the completed DUDE experiment. The [research evidence index](../reports/README.md) summarizes its results and the subsequent studies.

**Completed study: 660 audited main source clusters, with separate source/design and execution commitments.**

The source/design specification was prepared on 2026-09-26 and finalized after source-only review, before model outcomes. CPU request checks preceded the separate execution lock, which bound the runner, analyzer, configuration, model and runtime before generation. These are local timestamped commitments rather than third-party preregistration. The original prospective draft is identified by SHA256 `c5ebbdf0a3ecf81a78edd4eb17bcc13b100bdb44a17a8fbad91b1a5666afe7be`. The scientific conditions below retain that design; this public documentation summarizes its completed chronology.

## Question and scope

Does source-render detail improve answer correctness compared with an enlarged crop reconstructed from the low-resolution overview, when region, prompt, image dimensions and processor grid are matched? The sole primary contrast is `native_256 minus degraded_256` on a custom binary exact-match outcome defined below.

The population is an audited subset of **DUDE training extractive questions**, one question from one provided answer page per original-source cluster. A document can have many pages, but **the annotation-selected answer page is supplied to all four conditions**. Regional conditions additionally receive an annotation-derived ROI. Both page selection and region localization are privileged. This is not full-document DUDE evaluation, a page-retrieval test, a benchmark leaderboard submission, an evaluation of a deployable selector, or evidence of model internals. It is a new-domain replication of the controlled visual comparison, not a larger TAT-DQA sample. Public benchmark exposure during model pretraining remains unknown.

## Technical eligibility and geometry

Require `answer_type == "extractive"`, exactly one nonempty original `answers` string, at most 160 characters and 25 whitespace words, and one nonempty human bounding-box group. Every box must have finite supported coordinates, positive extent and the same valid answer-page index. No multi-page answer, list, arithmetic conversion, inferred answer, or unsupported page-index convention is admitted. Preserve originals; a variant cannot replace a bad canonical answer.

Validate Azure DUE page/token ranges and the mapping between human/Azure coordinates and the actual PDF page. Rendering is full **MediaBox**, RGB, at fixed 200 DPI, with predicted dimensions `ceil(MediaBox_extent * 200/72)` and actual raster verification. Require both dimensions at least256 and area at least2,097,152 pixels. A PDF render is not a claim about a scan's native acquisition resolution. Support only rotation0, UserUnit1, a valid MediaBox and contained valid CropBox. Raw human answer-page indices are zero-based; Azure original `readResults.page` must equal index+1, and PDF/DUE/Azure page counts and ordered word identities must agree. Exact source support and full-page inspection remain necessary checks of the page convention.

Azure original page units must be inches. Its physical width/height times200 must match the integer zero-origin DUE canvas within **2 pixels on each dimension**. Compare that canvas with both PDF MediaBox and CropBox physical extents converted at200 DPI, using the same two-pixel allowance. Select the unique matching frame; equal MediaBox/CropBox is unambiguous, but two distinct frames both matching within tolerance are excluded. If neither matches, reject. Azure original word-polygon bounding boxes, multiplied by200, must also match their DUE word boxes within2 pixels per coordinate. This is a fixed rounding/representation allowance, not permission to stretch annotation boxes arbitrarily or guess a canvas from one sample.

Map human and DUE word coordinates from the matched frame's top-left origin into the actual full-MediaBox raster. Let `(MW,MH)` be MediaBox extents in PDF points, `(RW,RH)` the full raster dimensions, `(CW,CH)` the DUE canvas dimensions, and `(FW,FH)` the chosen frame extents. Then `sx=(FW/MW)*(RW/CW)`, `sy=(FH/MH)*(RH/CH)`, `dx=(frame.x0-media.x0)*RW/MW`, and `dy=(media.y1-frame.y1)*RH/MH`. Use `x'=dx+sx*x`, `y'=dy+sy*y`; floor lower and ceil upper rectangle edges after correcting only floating noise within1e-9 of an integer. Require input/output boxes in frame. No tolerance expands the human annotation itself. Actual source rasters must match the verified dimensions exactly; orientation and evidence alignment are visually reviewed.

Require a whole-token consecutive OCR span matching the canonical reference using casefold and whitespace collapse only. For **every matched word**, its center must lie inside at least one human rectangle and at least **50% of its area** must be covered by the true union of human rectangles. Compute union intersection without double-counting overlapping boxes. Flag partial coverage; it is not a full-word-box containment claim. The final padded ROI must fully enclose all matched word boxes and all human rectangles. Preserve punctuation, signs, numbers, units and word boundaries. Reject unresolved multiple matches. No fuzzy search, OCR correction, generated alias, PDF-text answer fallback or partial-token text cut. OCR/box agreement supports a technical candidate; it does not establish semantic correctness.

The ROI is the **union of all human annotation boxes** on that answer page, expanded on each side by twice the median matched canonical-word height, expanded to at least 256 by 256 source pixels and shifted inside the page without blank padding. Do not shrink the human region to the answer's word boxes. Require ROI area at most 25% of the rendered page, supported in-frame transforms, and processor-compatible dimensions. Bind actual geometry and the raw annotation origin in the sidecar audit. All variants admitted to primary scoring must be supported on this same page and within the same ROI.

## Finite source-only selection and semantic audit

The sampling seed is **20260927**. Sort clusters by `(SHA256("20260927:" + source_cluster_id), source_cluster_id)`. Within each document, order questions by `(SHA256("20260927:" + questionId), questionId)` and retain the first technically eligible one. Choose the minimum question rank among those first-pass questions of lineage-qualified documents in the cluster, using document rank as a tie-breaker. This is one fixed candidate per cluster; all representative-document and linkage decisions are bound. Never select a question because a VLM is uncertain or expected to improve.

For each proposed engineering/main example, inspect the full answer page and its context/ROI against the original question, canonical reference, original variants and annotation. Review must establish legibility, correct page/referent/row/date, quantity/sign/unit, canonical support, and whether relevant evidence or disambiguating context is missing. Source questions requiring unavailable pages are excluded. Record reviewer identity, inspected images, support/rejection rationale, and category. The source screening is descriptive and does not constitute independent expert validation. Resolve conflicting reviews before inclusion; unresolved cases are excluded conservatively.

Validate the canonical original string first. If it fails semantic review, **exclude the cluster's selected QA and skip that cluster**; do not choose a more convenient alternate question from it. Continue down the pre-ranked cluster list. For variants, approve only unchanged strings already present in the original `answers_variants`, individually supported by the same source page/ROI. Unsupported variants may be rejected while a valid canonical QA remains; preserve every variant's decision. Do not add punctuation fixes, unit substitutions or newly written alternative answers.

Audit **all 660 proposed main questions**, not a small sample, before final inclusion. The finite review universe is at most one technically selected candidate per available lineage-qualified source cluster; stop after 660 main approvals or after exhausting that universe. The engineering exclusions are removed first. Record every attempted and skipped rank and the complete source-only exclusion ledger. A cluster never returns after seeing a model response. If fewer than 660 main clusters pass, do not relax eligibility or silently run a smaller confirmatory study: revise the intended scope, N and power statement explicitly before any main outcome collection.

Every earlier rank must resolve to a bound approved source, a reasoned source-only rejection, or a deterministic preparation/geometry exclusion. A missing review is not a rejection. Transient file, renderer or infrastructure failures require repair/re-render and cannot silently advance the selection order. Reviews, including rejections, record reviewer identity, timestamp, rationale and the exact source-audit hash. Finalization must verify agreement among census candidate, rendered manifest, technical audit, image hashes and semantic review; a self-consistent file hash alone does not establish that their question, reference, source, page or ROI fields agree. Record all ten additional engineering reservations even if some are rejected; establish a sufficient separate engineering cohort before future model execution, without returning reserved sources to main.

The finalized manifest contains `source_cluster_id/source_id`, original `doc_id`, question ID, original question, `original_answers`, `original_answer_variants`, technical `ocr_supported_answers`, source-reviewed `validated_primary_answers`, explicit `answer_page_privileged=true` and `roi_privileged=true`, PDF/annotation/OCR/image hashes, actual pixel dimensions, `answer_page_index`, `roi_pixels`, cohort/rank and semantic-audit identity/hash. Initially empty `validated_primary_answers` or pending audit status is a lock blocker. The canonical raw original must remain among validated answers. Annotation text and OCR are never prompt inputs.

## Frozen model and four requests

Use **Qwen/Qwen3-VL-4B-Instruct**, revision `ebb281ec70b05090aa6165b016eac8ec08e71b17`, BF16, SDPA, greedy decoding, 64 newly generated tokens and the unchanged `ANSWER:` assistant prefix/parser. Reuse the existing v5 request builder and pixel-budget behavior without changing those frozen files. Pin the new runner separately. No fine-tuning, search, confidence routing or second backbone enters this primary study.

| Action | Supplied pixels | Nominal visual-token ceiling |
|---|---|---|
| `direct_256` | Provided answer-page overview | 256 |
| `native_256` | Same overview + source-render ROI | 256 + at most 1024 |
| `degraded_256` | Same overview + matched ROI reconstructed solely from that overview | 256 + at most 1024 |
| `highres` | Same provided answer page, higher resolution | 4096 |

All requests are fresh and independently constructed. There is no prior assistant answer or shared KV state. Native and degraded use identical chat bytes, identical first-image pixels and identical second-image dimensions/geometry. Native crops use source pixels with no upsampling. Degraded crops use the same source ROI projected with floating-point coordinates into the actual overview, then BICUBIC-resized to the native crop's exact output size. Use the existing 32-pixel-grid bounded sizing and reject processor minimum-resolution upsampling. Actual grids/tokens must be recorded; the ceiling need not be filled.

The system instruction stays `You answer questions accurately based on the provided images.` The exact answer instruction stays `Answer by copying the relevant single text span from the page, including any units. Do not explain.` Direct/highres append it to the original question. Both regional prompts prepend `The first image is the full page. The second image is an enlarged region of the first image.` No reference string, OCR, evidence description, coordinates, source label, action name or variant enters model language input.

## Scoring fixed before outcomes

**Primary: custom source-validated exact match**, `primary_em`. Parse the full response using the unchanged frozen parser. Normalize parsed prediction and each approved reference by Unicode `casefold()` and collapsed whitespace only. Accept equality to any `validated_primary_answers`. Preserve punctuation, articles, numeric formatting, signs and units; no substring extraction or semantic judge enters this score. This is explicitly not official DUDE EM and differs prospectively from v5's TAT-QA-derived primary outcome. Invalid/empty parser outputs receive zero. Truncation is flagged and retained; a valid parsed truncated response is scored as produced.

**Secondary: author DUDE scalar ANLS**, applied to the same parsed answer and unchanged `original_answers` only. Pin [DUDEeval](https://github.com/Jordy-VL/DUDEeval/blob/8bd6deac0f9747e344338e3850f02bf76744d888/evaluate_submission.py), commit `8bd6deac0f9747e344338e3850f02bf76744d888`, evaluator SHA256 `df11012257fc9650af0d696be8b171d27ed9eebdc659dd9dcb660233d8806f4d`. Its non-list path ignores `answers_variants`. It computes character edit distance after lowercasing/whitespace collapse, but divides by the maximum **original upper-case string length**, and retains similarity exactly 0.5. Preserve these quirks. Invalid parser output is an explicit zero at the study's response layer; do not exploit whitespace/empty-string quirks. The adapter covers this scalar extractive subset, not lists, unanswerable questions or whole-benchmark aggregation. Report all ANLS values without retuning the threshold.

`experiments/dude_metrics.py` provides `score_response(response, official_answers, validated_answers, official_answer_variants=())`; map those arguments to `original_answers`, `validated_primary_answers`, and `original_answer_variants` from the finalized manifest. It rejects invented validated strings or removal of the canonical reference. Source support still requires the separate audit. Do not import TAT-QA normalization or reuse the older diagnostic ANLS as official DUDE scoring.

## Primary inference, power and advancement

The target is **N=660 distinct audited source clusters**, 2,640 main calls. The primary statistic is the mean of within-cluster `primary_em(native_256)-primary_em(degraded_256)`. Report each action's mean, both discordant counts (native-only and degraded-only correct), raw/parsed agreement, failures and sample coverage. Use a two-sided exact McNemar test at alpha=.05, with positive observed direction required for evidence of benefit. The formal test is fixed; do not replace it with mid-p/asymptotic testing or select ANLS as primary after outcomes.

The planning alternative is +5 percentage points against zero, assuming total native/degraded discordance q=.20 and independent clusters. Exact positive-direction rejection probability at N660 is approximately **80.19%**; sensitivities q=.08/.15 and effects +3/+3.5 pp remain relevant. This probability is a scenario assumption for the new custom binary metric, not a power guarantee inferred from TAT-DQA or from the new metadata. It is not power for ANLS, evidence that the true effect exceeds 5 pp, or the probability of satisfying the complete advancement rule. Residual source dependence or different discordance changes power.

Report a 95% paired percentile bootstrap CI using 10,000 resamples, seed20260927; resample entire source clusters and all four action outcomes together. Exact McNemar and this CI are not test/interval inversions and may disagree at a boundary. Report both without choosing the favorable result. Degenerate empirical intervals do not establish equivalence. Secondary ANLS contrasts, native/degraded versus direct, highres quality/cost and slices are descriptive/unadjusted and cannot replace the primary result. Do not pool earlier development panels into this estimate.

Prospective quantitative advancement requires positive primary difference, observed difference at least 2 pp, exact two-sided p<=.05, paired CI lower bound>0, and native primary EM at least direct primary EM. The 2 pp point-estimate threshold plus CI lower>0 does not establish a true effect greater than 2 pp. Passing motivates a separate untouched evaluation of nonprivileged region selection; it never starts controller training automatically. A failed/uncertain result is reported with its interval, not recast as equivalence.

After completion, conduct condition-blinded descriptive review of **all native/degraded parsed-answer changes**, including both-correct/both-wrong cases and differing raw responses when either parse is invalid. Fix per-case A/B randomization with seed20260927; show full page, original question/reference and full raw answers without action labels or scores. Freeze judgments before unblinding. Categories: content difference, formatting-only, both valid, both wrong, ambiguous. Report native-only content repairs, reverse harms and uncertainty; require at least three distinct unambiguous native-only repairs and positive net repairs as an additional descriptive screen. This screen cannot rescue a failed quantitative rule or change any automatic grade.

## Cost, integrity and two separate locks

Primary cost is each **standalone** synchronized VLM invocation; fresh crop calls do not require a direct answer. Secondary decision-state cost adds the matched direct256 latency to each regional call and uses the maximum sequential peak memory; direct/highres stay standalone. Neither includes the unavailable real-world cost of discovering the privileged page/ROI. Separate PDF/annotation preparation, model loading, warmup and logging. Report all latency observations with mean/median/p95/max, allocated/reserved memory, actual input/visual/generated tokens and total runtime. Do not claim equal compute, stable speed or energy savings from nominal token ceilings.

**Source/design lock:** bind original release/lineage/archive hashes, source-cluster links, every attempted candidate/exclusion/semantic audit, the exact660 main manifest, all ten additional engineering reservations and their reviewed manifest, the separate known-probe cluster exclusion, actual image/ROI provenance, renderer/adapter/metric hashes, upstream evaluator/license, fixed scientific questions/statistics, model revision and literal prompts. Record protocol/config hashes and a source/design-lock timestamp. All included source reviews must be approved; unresolved exclusions/ranks block this lock. The preparation artifact records `final_selection_frozen=true`; generation additionally requires a separate execution lock.

**Execution lock:** bind the verified runner and strict analyzer hashes, unchanged v5 request/backend dependencies, runtime/model/processor identity, previously locked source/design artifacts, exact action/generation parameters, output run identity and a distinct execution-lock timestamp. The completed experiment used this separate commitment after source preparation and before model generation.

The completed-run analyzer requires all 2,640 paired main rows, unique planned source clusters, no engineering/main overlap, immutable references, complete grade reconstruction, pixel/chat/ROI/grid identity checks and an explicit run-completion record. CPU request reconstruction is preparation evidence, not captured model activations or a completed inference study. A zero native/degraded pixel/tensor difference is recorded and retained, not used to remove a source or change its ROI.

Generation requires both source/design and execution commitments with all required bindings. No interim quality peeking, significance-based stopping, post-outcome answer-variant additions, sample extension or difficult-case substitution. Engineering-only bug fixes are documented and re-frozen before main. If a main engineering failure requires a scientific input change, stop and preserve the failed run rather than merge incompatible outputs. The five earlier experiments retain their original records. This protocol evaluates the matched-detail contrast; method novelty, transfer, learned-policy performance and causal internal-attention mechanisms are outside its scope.
